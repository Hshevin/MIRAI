# MIRAI 交互与功能改进路线图

> 状态：规划中 · 起草于 2026-11-09 · 基线提交 `cebe96e`（双语深色工作台重构之后）

本文档记录重构后仍然存在的交互和功能短板，以及修改计划。每一项都写明了"现在的问题"、"改法"和"依赖"，并按优先级分组。所有改动都必须遵守 `AGENTS.md` 中的隐私不变量：**不确定的像素一律遮蔽**、修订版本不可变、任务绑定到具体修订版本。

优先级说明：
- **P0**：直接影响"能不能放心导出"，应当最先做。
- **P1**：明显提升效率或减少误操作。
- **P2**：体验打磨、规模化和工程保障。

工作量是粗略估计：S 不超过 1 天，M 为 2–4 天，L 为 1 周以上。

---

## P0：让用户在导出前就能确认结果

### 1. 编辑器内实时遮蔽预览
- **现在的问题**：编辑器播放的是原始视频。用户看不到谁会被遮蔽、遮蔽到什么范围，只能等"生成预览"渲染完（固定为前 10 秒）才知道。
- **改法**：
  - 在视频上叠一层 canvas。按当前帧的检测结果绘制：保留的人物画薄荷绿描边；其他人和不确定的人画半透明马赛克或斜线填充。修正和标注的效果立即反映在这层上。
  - 播放器加一个"原始 / 遮蔽预览"开关（快捷键 `M`）。
  - 这只是近似效果。界面上要注明"最终以渲染结果为准"，因为 SAM 精修和羽化只在渲染时才做。
- **依赖**：时间轴接口需要支持按时间窗口返回 `mask_polygon`。目前只返回 box。
- **工作量**：M

### 2. 在画面上直接点人来修正
- **现在的问题**：要修正某个人，用户得先在时间轴上拖出一个时间段，再到右侧列表里按"轨迹 #n"找对应的人。这个映射关系完全要靠用户自己去对照。
- **改法**：
  - 新增"选择"工具（快捷键 `S`，作为默认工具）。点击画面中的某个人，就选中他所在的轨迹：时间轴高亮对应轨道，右侧显示这条轨迹的卡片（缩略图、时间范围、当前可见状态）。
  - 卡片上提供三种范围的"可见 / 遮蔽"操作：整条轨迹、当前时间段、从当前时刻到轨迹结束。
  - 点标注和框标注退居为"精修工具"，只用于调整掩膜细节。
- **依赖**：前端按 box 做命中测试即可，不需要后端改动。轨迹缩略图可以先从代理视频截帧。
- **工作量**：M

### 3. 逐个审核不确定片段
- **现在的问题**：不确定片段默认被遮蔽，这是安全的。但用户不知道一共有几处，也没有办法逐个过一遍。"本来应该保留的人被遮蔽了"这种错误很容易漏到导出结果里。
- **改法**：
  - 修正面板顶部显示"待审核：3 处不确定"。
  - 提供 `N` / `Shift+N` 跳到下一处或上一处：自动定位到该片段、选中对应轨迹，并循环播放这一小段。
  - 用户点"确认是 P001"（纳入）或"不是"（保持遮蔽）后，该处标记为已审核。"保持遮蔽"也要能被记录下来，以区分"没看过"和"看过但决定遮蔽"。
- **依赖**：
  - 后端需要一种不改变结果、只记录"已审核"的修正类型。可以考虑给 `IdentityOverride` 增加 `decision="confirm_hidden"`，或新建 `ReviewMark` 表。这属于 schema 变更，需要同步更新 `AGENTS.md`。
- **工作量**：M

### 4. 导出前检查
- **现在的问题**：点"导出视频"会直接排队，用户不会被提醒任何潜在风险。
- **改法**：导出前弹出一份检查清单，列出：
  - 还有几处不确定片段未审核；
  - 是否开启了专家模式及具体参数；
  - 当前预览是否基于旧版本（已过期）；
  - 音频不会做匿名化处理。

  对于前两项，用户需要显式确认后才能继续导出。
- **依赖**：第 3 项（统计未审核数量）。
- **工作量**：S

### 5. 可以删除单个标注或修正
- **现在的问题**：修订链是不可变的，只能整体"撤销"或回到某个历史版本。如果用户想删掉 5 步之前的某个点标注，就得回到那个版本，再重做后面的所有步骤。
- **改法**：
  - 新增一种"撤回"类修订，它引用被撤回的那个修正的 ID。`resolve_selection` 在汇总时跳过已撤回的修正。这样不可变性依然保持，同时可以针对单项操作。
  - 前端在"已保存的修正"和新增的"标注列表"里，给每一项加删除按钮；画面上的标记也支持选中后按 `Delete` 删除。
- **依赖**：后端 schema 和接口变更（新增撤回修订、修改 `resolve_selection`），需要补测试并更新 `AGENTS.md`。
- **工作量**：M

## P1：效率与少犯错

### 6. 预览可以指定片段
- **现在的问题**：预览固定渲染前 10 秒。如果问题出在第 5 分钟，预览就帮不上忙。
- **改法**：预览任务接受 `start_us` / `end_us` 参数，前端默认取"当前选中的时间段"，没有选中时取"播放头前后 5 秒"。预览结果与原视频按同一时间点同步播放，可以并排对比，也可以用滑块切换对比。
- **依赖**：后端 `create_revision_job` 的 payload 需要支持时间段，`render_video` 需要支持起始位置。
- **工作量**：M

### 7. 合并 / 拆分人物身份
- **现在的问题**：同一个人如果被 Re-ID 拆成了 P001 和 P004，用户只能逐条轨迹去手动纳入；反过来，如果两个人被误合成了一个身份，也没有办法拆开。
- **改法**：
  - 在选人页支持多选，提供"合并为同一人"操作。
  - 在编辑器的轨迹卡片上提供"这不是 P001"操作，将该轨迹整体排除。
  - 合并操作要作为修订记录下来，而不是直接修改分析结果。
- **依赖**：
  - 选择修订需要支持多个 `person_id`，或者用一组纳入修正来实现合并效果。
  - 无论哪种方式，都不能违反"时间重叠的轨迹不能自动归为同一身份"这条不变量。如果用户手动合并了时间重叠的轨迹，界面必须给出警告。
- **工作量**：L

### 8. 项目列表与多视频管理
- **现在的问题**：后端没有列出视频的接口，前端只能从 `localStorage` 恢复"最后一个"视频。用户无法回到更早处理过的视频，也无法删除视频来释放磁盘空间。
- **改法**：
  - 新增 `GET /videos` 和 `DELETE /videos/{id}`。删除需要级联清理该视频的产物目录。
  - 上传页下方显示"最近项目"列表：缩略图、状态、最后修改时间。
  - 任务抽屉里每个任务都加"打开"按钮，可以直接跳到对应视频。
- **依赖**：后端新增接口、存储清理逻辑。
- **工作量**：M

### 9. 长视频时间轴：缩放、过滤、降采样
- **现在的问题**：
  - 时间轴接口一次性返回整段视频的全部检测结果。30 分钟、多人物的视频会有几十万行数据。
  - 时间轴不能缩放，轨道太多时每条只剩 1 像素高。
- **改法**：
  - 后端新增聚合接口：按时间分桶返回每条轨迹的类别，只在当前可见窗口里返回逐帧明细。
  - 前端支持缩放：`⌘+滚轮` 或 `+` / `-` 键缩放，拖动平移；时间刻度上方加一条缩略帧条带。
  - 轨道支持过滤：只显示保留人物和不确定的轨道、折叠其他人；可以按人物分组显示。
- **依赖**：后端新增聚合接口。
- **工作量**：L

### 10. 逐帧精确定位
- **现在的问题**：方向键每次移动固定 0.1 秒。对于可变帧率（VFR）视频，这既不等于"一帧"，也违背了"按实际 PTS 定位"的原则。
- **改法**：
  - 用 `requestVideoFrameCallback` 获取实际帧时间，方向键改为跳到上一帧或下一帧。
  - 时间码改为显示"帧号 + 时间"。标注的 `timestamp_us` 对齐到最近一帧的真实时间戳。
- **依赖**：可能需要一个返回帧时间表的接口（数据库已有 `Frame.timestamp_us`）。
- **工作量**：M

### 11. 任务进度推送与失败信息
- **现在的问题**：
  - 前端每秒轮询一次整个任务列表。
  - 失败时直接显示后端的原始报错文本，用户不知道该怎么处理。
  - 本机没有 CUDA 时，分析任务也可以提交，等到运行时才失败。
- **改法**：
  - 改用 SSE 推送任务进度。
  - 把 `error_code` 映射为本地化的说明和处理建议，例如"未检测到 CUDA → 分析需要 NVIDIA GPU"，并提供"复制诊断信息"按钮。
  - 健康检查显示 CUDA 不可用时，分析按钮要提前提示，不要让用户提交了才失败。
  - 页面在后台标签页时，任务完成用浏览器通知提醒。
  - 失败的任务提供"重试"按钮。
- **工作量**：M

### 12. 上传体验
- **现在的问题**：
  - 大文件上传中断后只能从头再传（上限是 20 GB）。
  - 文件格式、时长、分辨率要等上传完才由服务端校验，问题发现得太晚。
- **改法**：
  - 改为分片上传，支持断点续传。
  - 上传前先在浏览器里读取视频的元数据（时长、分辨率），超出限制当场提示。
  - 支持一次拖入多个文件，按顺序排队上传。
- **依赖**：后端分片上传接口。
- **工作量**：L

### 13. 参数调节的即时反馈
- **现在的问题**：调整马赛克大小、模糊强度、边缘羽化时，只能看到数字变化，看不到实际效果。
- **改法**：在效果面板顶部加一个示例帧小窗，用 canvas 在前端近似渲染马赛克和模糊效果，拖动滑块时实时更新。边缘外扩和羽化在第 1 项的遮蔽预览层上直接体现。
- **工作量**：S

### 14. 音频处理选项
- **现在的问题**：音频始终原样保留。这是有意的设计，但如果用户确实需要处理音频，目前没有任何选择。
- **改法**：导出时提供三个音频选项：保留（默认，当前行为）、静音、移除音轨。所选选项写入修订版本的设置快照，导出页明确显示当前选择。
- **依赖**：`RenderSettings` 新增字段，混流（mux）阶段增加对应分支，并更新 `AGENTS.md` 中的产品描述。
- **工作量**：S

## P2：打磨、无障碍与工程保障

### 15. 新手引导与快捷键帮助
- 首次进入编辑器时，用 3 步引导依次介绍：画面工具、时间轴、导出。
- 按 `?` 打开快捷键速查面板。
- 工具栏的 tooltip 统一显示对应的快捷键。

### 16. 修订分支可视化
- **现在的问题**：用户回到某个历史版本后再做编辑，原来的后续版本就成了"孤立分支"，历史面板里看不到它们。
- **改法**：历史面板改为树状显示，孤立分支灰显，并支持切换回去。回到旧版本时提示"之后的修改会形成新分支"。

### 17. 无障碍与细节
- 人物卡片网格支持方向键导航。
- 切换步骤时，焦点自动移到新页面的标题。
- 支持系统的 `prefers-reduced-motion` 设置（减弱动画）。
- 时间轴为屏幕阅读器提供文字摘要，例如"共 5 条轨迹，2 处不确定"。
- 导出文件名带上原视频名和版本号，例如 `street-interview.P001.r6.mp4`。

### 18. 演示模式与端到端测试
- 把这次临时写的合成演示数据脚本移入仓库，作为 `scripts/seed_demo.py`。在 `launch.sh` 中增加 `--demo` 参数：使用独立的运行目录，不需要 GPU 或 SAM 就能体验完整流程。
- 用 Playwright 加上述演示数据编写端到端测试，覆盖：选人、打标注、时间段修正、调参数后修正仍然保留、撤销、预览、导出。
- 用 React Testing Library 为 `CorrectionsPanel`、`SettingsPanel` 等组件补单元测试。
- 前端增加 lint（ESLint，含 react-hooks 规则），并在 CI 中运行。

### 19. 已知环境问题
- 在 macOS 上，`.venv` 里的 `.pth` 文件会被加上 hidden 标志（疑似与 `~/Documents` 的同步有关）。Python 3.12 会跳过这类文件，导致 editable 安装失效。
- 需要查明原因，并在 README 中写明规避方法，例如把 `UV_PROJECT_ENVIRONMENT` 指向不受同步影响的目录。
